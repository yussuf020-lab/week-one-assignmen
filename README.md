EXERCISE A: EXPLAINING THE SDLC

Prompt 1: Zero-Shot

Question/Prompt:

Explain the Software Development Life Cycle (SDLC), including its main phases and the purpose of each phase.

Answer:

The Software Development Life Cycle (SDLC) is a structured process used to develop and maintain software. It normally includes planning, requirements analysis, system design, development, testing, deployment, and maintenance. Each phase has a specific purpose, such as understanding user needs, designing the system, writing the code, testing for errors, and maintaining the software after it has been released. The SDLC helps development teams organize their work and produce reliable software.

Summary:

The SDLC provides a clear process for developing software from the initial idea to maintenance. It consists of several phases, with each phase focusing on a particular part of software development. Following these phases can help reduce errors, manage resources, and improve the quality of the final system.

Prompt 2: Role Prompting

Question/Prompt:

You are an experienced software engineering instructor teaching first-year university students. Explain the Software Development Life Cycle (SDLC) using simple and beginner-friendly language. Organize the answer using headings and bullet points, and give a short practical example for each phase. End with a brief explanation of why the SDLC is important.

Answer:

Meaning of SDLC

The Software Development Life Cycle (SDLC) is a step-by-step process used by software developers to plan, build, test, release, and maintain software.

1. Planning

The team decides what the project is about, what it should achieve, what resources are needed, and what challenges might occur.

Example: A university decides to develop an application that allows students to book study rooms.

2. Requirements Analysis

The team finds out what users and the organization need from the system.

Example: Students may need to see available rooms, choose a time, and make a booking.

3. System Design

The team decides how the software will look and how it will work technically.

Example: Developers design the application screens and decide how booking information will be stored.

4. Development

Programmers write the code and create the different features of the software.

Example: Developers create the login, room availability, and booking functions.

5. Testing

The software is checked for errors and to make sure that it meets the requirements.

Example: Testers check that two students cannot book the same room at the same time.

6. Deployment

The completed software is made available to its intended users.

Example: The university releases the study-room application for students to use.

7. Maintenance

The system is monitored and updated when problems occur or improvements are needed.

Example: Developers fix a booking problem reported by students.

Why the SDLC is Important

The SDLC helps a software development team work in an organized manner. It improves communication, helps identify problems early, and provides a clear way of managing the project from beginning to end.

Summary:

The second prompt was more useful because it was easier to understand and included practical examples. I changed the prompt by adding a specific role, audience, and format. The role encouraged a teaching style, while identifying first-year university students encouraged the use of simple language.

Comparison:

The second response was more useful because it was more organized and practical. The role and audience helped make the explanation easier for beginners to understand. Adding examples and headings also made the information clearer.

EXERCISE B: SOFTWARE DEVELOPMENT MODELS

Question/Prompt:

You are a software engineering consultant helping a company choose appropriate software development models. Explain which development model would be most appropriate for each of the following situations:

1. A project with stable and clearly defined requirements.
2. A startup where requirements change frequently based on user feedback.
3. A large project with significant technical and security risks.
4. A project where testing and verification are extremely important.

For each situation, recommend a suitable development model, explain why it is appropriate, and mention one limitation of the model. Present the answer in a clear table.

Answer:

1. Stable and clearly defined requirements

Development Model: Waterfall Model

Reason: Waterfall is suitable when requirements are well understood and unlikely to change.

Limitation: Changes later in the project can be difficult and expensive.

2. Startup with frequently changing requirements

Development Model: Agile Model

Reason: Agile allows development in short cycles and supports regular user feedback and changes.

Limitation: Frequent changes can make long-term planning difficult.

3. Large project with technical and security risks

Development Model: Spiral Model

Reason: Spiral focuses strongly on identifying and managing risks throughout development.

Limitation: It can be expensive and requires experienced management.

4. Testing and verification are extremely important

Development Model: V-Model

Reason: The V-Model gives strong attention to testing and verification throughout development.

Limitation: It is less flexible when requirements change.

Reflection:

I learned that choosing a software development model depends on the characteristics of the project. Stable requirements can work well with a sequential model, while changing requirements need a more flexible approach. Projects with high technical risks need strong risk management, while projects where testing is very important need a model that emphasizes verification.

EXERCISE C: REQUIREMENTS EXTRACTION

Question/Prompt:

Act as a business analyst and requirements engineer. Analyze the following bookstore requirements and organize them into:

1. Functional requirements.
2. Non-functional requirements.
3. Must Have requirements.
4. Should Have requirements.
5. Nice to Have requirements.
6. Questions or ambiguities that need clarification.

Do not invent requirements that are not supported by the brief.

Client Brief:

A local bookstore needs software to:

* Track books, quantities and prices.
* Manage supplier payments.
* Alert staff when stock is low.
* Identify best-selling books.
* Allow customers to check availability online.
* Produce clear records for a part-time assistant.
* The owner has a limited budget.

Answer:

Functional Requirements:

1. Store and manage book information.
2. Record book quantities and prices.
3. Update stock information.
4. Manage supplier payments.
5. Alert staff when stock is low.
6. Track sales and identify best-selling books.
7. Allow customers to check book availability online.
8. Produce clear records for the part-time assistant.

Non-Functional Requirements:

1. Usability: The system should be easy for staff to use.
2. Affordability: The system should fit the owner's limited budget.
3. Reliability: Stock, sales, and payment information should be stored accurately.
4. Security: Business and payment information should be protected.
5. Performance: Online availability information should load within a reasonable time.
6. Maintainability: The system should be easy to update and maintain.

Must Have Requirements:

* Book and inventory management.
* Quantity and price tracking.
* Supplier payment records.
* Low-stock alerts.
* Identifying best-selling books.
* Online book availability.
* Clear records for staff.
* Affordable implementation.

Should Have Requirements:

* User-friendly interface.
* Book search functionality.
* Basic sales reports.
* Access controls for sensitive information.

Nice to Have Requirements:

* Dashboard showing sales and stock.
* Advanced sales reports.
* Email or SMS low-stock notifications.
* Detailed sales analysis.

Questions and Ambiguities:

1. Can customers only check availability, or can they also purchase books online?
2. How should supplier payments be recorded?
3. Should the system connect to a bank or payment service?
4. What quantity should trigger a low-stock alert?
5. How should a best-selling book be determined?
6. Should the part-time assistant have the same access as the owner?
7. What devices will staff use?
8. What is the exact budget?
9. Does the bookstore already use accounting or inventory software?
10. What backup and security requirements are needed?

Evaluation:

Two things the response did well:

1. It clearly separated functional requirements from non-functional requirements.
2. It identified important questions, such as the definition of a best-selling book and the low-stock threshold.

One thing it missed or categorized incorrectly:

Basic sales reports and search functionality were placed under Should Have. Depending on the bookstore's needs, these could possibly be Must Have requirements.

One improvement:

I would ask the AI to create a traceability table showing which part of the client's brief supports each requirement. This would make the requirements easier to verify.

OVERALL REFLECTION

What makes a prompt effective?

An effective prompt should be clear, specific, and provide enough context. It should explain what is required and, when necessary, specify the expected format and audience.

Which prompting technique did you find most useful?

Role prompting combined with detailed context was the most useful. It helped the response become more professional and relevant to the specific task.

Why is context important when working with AI?

Context helps the AI understand the situation, users, requirements, limitations, and purpose of the task. Without context, the response may be too general or contain assumptions that do not fit the project.

Why should we review AI-generated responses?

AI-generated information can contain errors, missing requirements, unrealistic assumptions, or incorrect classifications. Reviewing the response helps ensure that the information is accurate and appropriate before it is used in a real project.

How can AI support software engineers across the SDLC?

AI can support planning by creating schedules and identifying risks. It can help analyze requirements, suggest system designs, assist with programming and debugging, generate test cases, support deployment documentation, and help troubleshoot problems during maintenance. AI can therefore save time and support software engineers throughout the SDLC, while human review remains important for important technical and business decisions.
